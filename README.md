# Reward Systems- rubric judge学习笔记

## 摘要

Rubric 是一套把抽象目标拆成具体判断标准的规范，既可以指导离线数据合成，也可以作为 Agentic RL 的奖励接口。现有研究已经从“把评分标准写得更详细”，推进到“让标准可核验、随策略变化而调整，并真正促进学习”。本文围绕这一问题梳理诊断和合成、训练效用反馈、奖励聚合、在线演化、证据和过程信用等研究方向，比较各类方法的优化对象、实验结论和适用边界，并讨论训练效用识别、自然错奖修复、旧能力保持等开放问题。

## 一、问题背景

### 1.1 什么是 Rubric

Rubric 是一套**把抽象目标拆成具体判断标准的规范**，通常说明应该检查什么、什么情况下适用、依据什么证据、怎样判定满足程度，以及不同判断如何合并。

以“修改数据库中的指定记录，其他记录保持不变”为例，标准可以包括：

- **对象正确**：查询条件、对象标识和任务要求匹配
- **写入正确**：写入后读取的实际状态符合要求
- **无副作用**：操作范围和前后状态差异证明未误改其他对象
- **报告准确**：最终回复和实际执行结果一致

**Rubric 是标准，judge 是执行标准的评分者，reward 是最终进入训练的数值。** 相同 rubric 交给不同 judge，可能得到不同判断；逐项判断相同，采用不同聚合方式，也可能形成不同训练激励。

完整的 rubric system 还包括规则内容、适用条件、证据接口、判断器、聚合机制，以及规则生成、更新、选择、停用和接入训练的生命周期。因此，规则正确、证据充分、判断准确、聚合合理、训练有用，是不同层面的要求。

### 1.2 从评分标准到学习信号

“离线／在线”和“数据合成／RL”不是同一个划分：

- **离线固定**：在主要生成或训练前构建规则，使用期间基本不更新
- **在线演化**：根据当前策略的输出、错误或训练状态修改规则
- **数据合成**：指导样本生成、筛选、排序或标注，也可以生成训练 judge 的反馈
- **RL 奖励**：对当前策略的 rollout 评分，形成奖励或偏好信号

预先生成的固定 rubric 完全可以用于 on-policy RL，RaR 就是例子。[7] 即时生成规则也不等于维护了持续演化的规则系统：即时实例化、长期规则记忆和生成器参数更新是不同机制。

实际奖励可以来自已有 LLM 按显式 rubric 逐项评分，也可以来自偏好数据训练的 RM，InstructGPT 是后一类流程的代表。[22] 前者便于修改和审计，后者能吸收样本中的细粒度偏好；两者都依赖已有参数，也都可能产生误判和被策略利用。只要最终给出适用的标量奖励，都可接入 PPO、GRPO 等训练流程。

### 1.3 问题的重要性

**Rubric 同时位于“目标定义”和“学习信号”之间。** 离线合成中，它决定模型看到什么数据；RL 中，它决定哪些行为被强化。系统性的小偏差会通过数据筛选和反复策略优化被放大。

离线流程容易出现规范覆盖不足、模板和风格偏置、标签循环、过滤器误拒有效替代解法，以及评分质量和训练价值脱节。在线 RL 中，规则还可能随策略变化而饱和、全部失败、被利用或偏离原任务；旧规则退出后，相应行为也可能退化。

对 agentic RL，模型声称完成任务并不等于外部状态真的满足目标。**语言上的合理性、执行上的正确性、训练上的有效性，需要在同一个闭环中对齐。**

### 1.4 为什么 LLM RL 会使用 Rubric

RL 的基础是从环境获得反馈：哪些行为应该被强化，哪些行为应该被抑制。数学、代码等任务可以通过标准答案、编译器或测试用例自动判定，但开放问答、写作、方案分析和复杂 agent 行为通常没有这样的统一检查器。即便最终成败可以判定，只给整条轨迹一个终局奖励，也难以说明中间哪一步值得学习。

早期 LLM 对齐常用人工偏好训练 RM，例如 InstructGPT。[22] 这条路线能把人类偏好写入评价模型，但需要持续收集偏好数据，整体标量分数也不容易解释具体违反了哪项要求。直接让 LLM 对答案打总分虽然降低了评价门槛，仍可能受到位置、长度、表达风格等表面因素影响。

Rubric 因而成为一种折中方案：**把模糊目标拆成多个较容易判断的要求，说明每项要求需要什么证据，再将逐项判断聚合成训练奖励。** 相比整体评分，它更便于定位错误、修改局部要求、生成训练数据和组织过程反馈；相比纯人工标注，它可以用已有 LLM 扩大评价规模，并将教师模型的判断蒸馏到更便宜的 judge 中。RaR 等工作进一步说明，这些结构化判断可以直接作为 on-policy RL 奖励。[7]

但从第一性看，rubric **不会自动把不可验证目标变成可验证事实**。如果没有环境状态、执行结果或独立标注作为依据，它只是把“整体判断”换成“逐项判断”。评价 reward system 的根本标准仍是：反馈是否对应事实、是否符合真实目标、是否能区分当前行为、是否能定位局部信用，以及带来的策略学习收益是否值得总验证成本。

因此，更合理的分工是：**环境产生事实，反事实实验分配信用，rubric 组织反馈，judge 降低评价成本。** Rubric 的主要价值不是替代环境，而是把环境证据和难以程序化的质量要求组织成可用于学习的信号。

### 1.5 我们任务的定位

我们的 text-to-SQL / 金融 agent 任务同时落在前述多个问题的交汇处，不能简单归为“可验证任务”或“纯离线合成任务”：

| 维度 | 我们的现状 | 核心难点 |
|---|---|---|
| 任务性质 | **半开放、半可验证**：最终 SQL 执行结果可以规则判定，但推理和方案质量仍依赖 rubric 主观评分；同一问题也有多条合法完成路径 | 硬执行对错和软过程质量不是同一层目标，维度得分高不一定导致最终 SQL 正确 |
| Rubric judge 的使用 | 已经在**离线数据合成／筛选**和 **RL 的 rollout 评分**中尝试使用 rubric judge | 同套标准的偏差可能先影响数据，再在策略优化中被放大；离线评分质量和在线训练收益必须分别验证 |
| 交互形态 | **长程多轮**：think → 调工具（kg_search / bash / SQL）→ 读 observation → 再 think；CoT 分散在每一轮，且没有 GT CoT | 最终执行结果延迟且稀疏，整条轨迹的过程评分不能直接回答哪一轮、哪个动作值得强化 |

因此，当前缺少的不只是更细致的整体评分，而是**局部信用分配**。最终 SQL 成败和整条轨迹的 rubric 得分只能说明结果好不好，不能直接说明哪次检索、哪步 SQL 修改或哪个中间动作真正促成或破坏了成功。需要把 rubric 从整条轨迹下沉到轮次／步骤，并用 SQL 执行结果、环境状态和反事实重跑校验局部奖励，避免把主观维度分和最终对错之间的相关性误当成因果贡献。

## 二、问题形成机制的分析

### 2.1 六个关键机制

**目标分解不完整**：抽象目标包含适用条件、例外和优先级。拆分标准时可能遗漏条件，也可能把可替代的成功路径误写成唯一流程。关键是区分**真正的任务约束**和**某一种实现策略**。

**证据不足**：工具调用被发出、工具返回成功、实际状态满足目标，是不同事实。若 judge 只看最终回答，自然语言润色无法补齐缺失的状态证据。

**聚合改变目标**：加权求和允许不同标准相互补偿，关键失败可能被其他易得分项抵消；但把所有要求都改成严格合取，也可能使奖励极其稀疏。ProRubric 展示了评分上涨但回答适当性下降的现象。[9]

**策略变化造成测量失效**：一项要求可以始终重要，但当前已经人人满足；也可以非常重要，但当前模型一次都做不到。两者都缺少组内差异。**语义重要性、当前可学习性、统计区分度，是三个不同属性。**[18]

**代理目标和真实收益存在距离**：规则合理、评分准确、当前有区分度、能指导一次答案修改、能促进多步参数学习，是五种不同结果，不能相互替代。[11]

**反馈闭环产生选择偏差**：生成器、judge、规则筛选器和最终评测若共享同一套偏好，系统可能越来越符合自己的测量方式。固定评测标准、更换评测模型、引入独立事实，分别约束不同问题。

### 2.2 核心矛盾

> **Rubric 既要准确表达稳定任务目标，又要随策略变化持续提供可学习信号；但当前最有效的测量标准，不一定是最有长期训练价值的标准。**

一个编辑可能短期帮助探索，长期却增加无效步骤；也可能前期收益不明显，随后才促进能力形成。训练初始化、采样和环境差异还会扰乱候选排序。RHyVE 对阶段和验证跨度的研究，以及 RARE 的配对续训分析，都说明真实学习过程需要直接测量。[6][13]

## 三、主要研究方向

### 3.1 诊断校准和规模化规则合成

代表工作：LLM-Rubric [1]、RIFT [2]、Prometheus 2 [3]、OpenRubrics [4]

**核心思路**：先把 rubric 当成测量工具，检查标准、权重和 judge 输出是否可靠；再用强模型或偏好对合成规则和评价反馈，降低人工成本。

**方法要点**：LLM-Rubric 使用多维人工标准、评分分布和校准映射预测人工评价；RIFT 用可控破坏和诊断探针检查规则质量。Prometheus 2 训练支持自定义标准的开放评价模型；OpenRubrics 从 chosen/rejected 对比生成规则，再按偏好标签一致性筛选。

**实验结论**：

- 校准评分和专门诊断探针在各自评价设置中优于未校准评分或直接询问模型
- 开放评价模型和合成规则在直接评分、偏好比较及奖励建模基准上取得改善

**局限性**：评价一致性不能代替策略优化后的独立能力验证；合成监督还可能继承来源模型或偏好标签的偏差。质量诊断适合做候选编辑的准入检查，训练效用仍需另外验证。

### 3.2 训练效用反馈和联合学习

代表工作：OptimSyn [5]、RHyVE [6]、Rubric-ARM [10]、EvoRubrics [11]

**核心思路**：不再只凭规则文本和当前评分统计选择规则，而是用目标模型的优化信息、真实续训结果或偏好判断训练规则生成器和评价者。

**方法要点**：OptimSyn 用目标模型梯度及影响估计衡量合成样本效用，再以 RL 优化 rubric 生成器；RHyVE 从相同训练状态启动短分支，结合能力阶段、验证跨度和稳定性部署奖励候选。Rubric-ARM 交替优化生成器和 judge；EvoRubrics 让策略和生成器共同演化，并用区分度、多样性、标准对齐和建设性等反馈。

**实验结论**：

- OptimSyn 在医学、人文社科合成数据任务中报告下游收益
- RHyVE 显示奖励选择和策略阶段、验证跨度有关；联合学习方法也报告了奖励建模或下游对齐改善

**局限性**：影响估计、偏好判断准确性和一次答案修订收益，都不等于在线多轮 actor 的真实参数学习收益。仅仅“用 RL 训练生成器”不足以形成新贡献，关键是证明效用更适合在线 agent 学习。

### 3.3 奖励接口、聚合和在线规则演化

代表工作：RaR [7]、OpenRS [8]、ProRubric [9]、ARBOR [12]、RARE [13]

**核心思路**：即使规则文字不变，逐项反馈、偏好比较和必要条件也能改变训练激励；进一步还可以随当前策略更新规则内容和共享规则记忆。

**方法要点**：RaR 将实例级 rubric 用作 on-policy RL 奖励；OpenRS 根据候选答案差异实例化成对标准；ProRubric 用协议级维度和失败条款减少错误补偿。ARBOR 从不同质量轨迹生成局部规则，经筛选、归纳和去重进入共享缓冲区；RARE 替换饱和标准并更新任务级 rubric。

**实验结论**：

- RaR、OpenRS 和 ProRubric 分别在医学、科学、奖励建模或临床咨询设置中报告结构化奖励的收益
- ARBOR 使 Qwen3-8B 在四个多跳 QA 任务上的平均 EM 从 46.9 提升到 48.9；RARE 的配对续训中，更新分支 20 步后平均领先静态分支 0.79 分

**局限性**：当前区分度和重评分统计不保证后续效用；整条轨迹的过程评价也不等于逐步因果信用。新增规则前，还应先判断问题是否本应由聚合结构解决。

### 3.4 证据约束和反奖励利用

代表工作：MetaRubric [14]、RLR³ [15]、CHERRL [16]

**核心思路**：减少无依据的满足判定，利用可验证通道、反事实案例和攻击诊断，让得分对应真实满足。

**方法要点**：MetaRubric 使用反事实提示和证据感知的逐项反馈，并在原始意图和参考评价约束下调整规则；RLR³ 将可验证标准交给信息抽取和确定性检查，其余交给 LLM judge，再进行分层聚合；CHERRL 注入已知 judge 偏差，构造可控奖励利用场景。

**实验结论**：

- MetaRubric 和 RLR³ 分别在医学问答、部分可验证视觉语言任务中报告错误奖励减少或下游改善
- CHERRL 展示了策略利用已知偏差的过程，以及日志诊断能够识别的异常

**局限性**：文本证据不等于实际工具状态；注入式漏洞也不能替代自然产生的未知漏洞。检测成功不等于自动修复成功，真正需要建立的是自然错奖、最小修复和未见错误泛化之间的证据链。

### 3.5 过程信用、无效规则恢复和预算测量

代表工作：ARCO [17]、RuACT [18]、ProCredit [19]、RRT [20]

**核心思路**：把反馈放到更可能可学习的位置，对全部失败和全部通过分别恢复监督，并在有限 judge 调用下选择信息量更高的标准。

**方法要点**：ARCO 学习和终局反馈一致的步骤级 rubric；RuACT 对全部失败的标准使用特权信息和奖励门控自蒸馏，对全部通过的标准拆分子标准。ProCredit 在中间环境状态运行可执行验收检查，以进展变化分配信用；RRT 用项目反应理论建模难度和区分度，以 Fisher 信息选择评分标准。

**实验结论**：

- ARCO、RuACT 和 ProCredit 分别在多跳 QA、医学科学任务或 AppWorld 等环境中报告训练收益
- RRT 在四个数据集上改善奖励质量和策略表现，半量标准预算下接近全量评分基线

**局限性**：和终局相容的步骤分数不唯一，不能直接称为因果信用；恢复当前无效监督也不等于长期保持旧能力。若环境已有可靠程序化过程奖励，它应当成为自然语言 rubric 的强基线。

## 四、方法比较和分析

### 4.1 各方法的设计维度对比

| 方法类别 | 核心机制 | 优化目标 | 主要优势 | 仍需证明 |
|---|---|---|---|---|
| 诊断和合成 | 校准、探针、偏好合成 | 测量质量和偏好一致性 | 可定位问题并扩展初始资源 | 分布变化后的训练收益 |
| 训练反馈和联合学习 | 影响估计、短分支、生成器训练 | 训练效用或判断准确性 | 更接近最终学习目标 | 代理误差、迁移和验证成本 |
| 接口、聚合和在线演化 | 逐项比较、门控、规则缓冲区 | 当前区分度和结果相关性 | 改变错误激励并适应策略 | 后续效用和原目标保持 |
| 证据和反利用 | 状态检查、反事实、攻击诊断 | 可核验违反和异常 | 错误具体，便于因果对照 | 未见漏洞和正常案例误拒 |
| 过程、恢复和预算 | 步骤反馈、自蒸馏、信息选择 | 终局一致性、通过率和信息量 | 改善稀疏反馈并节约评分 | 信用正确性和长期保持 |

这些机制可以组合，但实验需要隔离主要改变。规则文字、judge 输入和聚合方式同时变化时，收益很难归因于“更好的 rubric 编辑”。

### 4.2 核心权衡

**规则效度和训练效用**：更合理的标准可能让当前评分更准确，却不一定产生更多可学习行为；更有区分度的规则也可能只是区分了任务无关特征。

**监督锚点和共享 Judge**：系统普遍依赖人工偏好、黄金 rubric、终局验收或可执行检查。训练、修订、筛选和评测若都由同一 judge 完成，改善可能只是迎合该 judge，需要程序事实、独立模型或盲评提供对照。

**局部优化和真实总成本**：规则更严格可能增加误拒，聚合更严格可能造成零奖励，评分更省钱可能漏掉低频关键要求。规则生成、重评分、候选验证和编辑器训练都应计入成本，并和“同预算直接多训 actor”比较。

### 4.3 共同的关键发现

尽管各方法出发点不同，以下几点是共识：

1. **评分更好不等于训练更好**：和独立标注更一致，不能推出策略学习一定改善
2. **规则需要证据和适用条件**：文本合理性、执行正确性和训练有效性必须分别验证
3. **当前区分度不等于长期价值**：全部通过和全部失败都缺少组内信号，但需要不同处理
4. **不同实验结论不能直接横比**：医学评分、脚本质量、问答 EM 和工具完成率不属于同一排行榜

## 五、开放问题和未来方向

### 5.1 怎样度量“对学习有用”

需要建立规则统计、影响估计、短分支收益和长程真实收益之间的关系。可检验的进展是：低成本效用预测器在未见学习状态上，比方差、相关性和固定日程更准确地选择有效编辑，并且排序能跨随机种子、学习阶段和任务复用。

### 5.2 怎样发现自然错奖并修复机制

实际 agent 可能通过新操作序列、状态边界或对象混淆获得错误奖励。系统需要从自然轨迹和主动搜索中定位错误，再判断应修改规则、证据接口、judge 还是聚合。关键证据是**未见错误机制上的改善，同时正常成功案例通过率保持稳定**。

### 5.3 动态规则怎样保持任务语义和旧能力

标准可以变细，但原任务目标不能随训练悄悄变化。每条标准应保留来源、适用条件和对应任务要求，将可演化建议和持续有效的硬约束分开。低频但严重的错误也不能因当前很少出现而停止检查，评价应同时报告新任务表现、旧要求违反率和评分成本。

### 5.4 怎样获得可识别的过程信用并控制预算

给每一步打分不难，难的是判断这一步是否促成成功。状态检查、反事实分支和动作干预可以提供更强证据，但成本和环境可恢复性不同。应区分“和终局相容的步骤分解”和“经干预验证的动作贡献”，同时防止预算调度漏掉低频关键约束。

### 5.5 我们的三个潜在切入点

三条路线应共用基础设施、分别验证：一是用真实 RL 分支收益学习可迁移的**规则效用预测器**；二是以真实工具状态发现自然错奖，完成**可执行反例驱动的最小修复**；三是在固定评分和回放预算下，研究**旧能力监测和规则重新激活**。

共同基础是可信终局验收加待研究的过程奖励：$r(\tau)=r_{\mathrm{outcome}}(\tau)+\alpha s_{\mathcal R}(\tau)$。初期固定 judge、聚合方式和优化器，先建设训练分支收益测量器和逐项环境事实核验器，再由 pilot 结果选择主线。Actor 训练、元训练、开发和最终测试必须分开，最终测试不能反馈给编辑器。[21]

## 六、总结

Rubric systems 的关键问题可以归为三层：**目标是否表达正确、评分是否对应事实、产生的信号是否促进真实学习。** 离线合成通过数据选择影响模型，在线 RL 则把规则偏差带入持续变化的策略优化，两者都需要独立下游验证。

已有研究已经覆盖诊断、合成、训练反馈、奖励聚合、联合学习、在线演化、证据约束、过程信用和预算测量。简单加入动态更新、训练一个生成器或安排几个短分支，都不足以单独支撑新增贡献。

更有价值的切口是：真实 RL 编辑效用能否被学习并复用；可执行错奖能否被修复并改善未见行为；有限预算下能否在学习新能力时保持原有要求。最终需要形成可重复、可迁移、成本清楚的证据。

## 七、面向我们任务的四个验证方向

需要验证它们能否改善**半开放、长程多轮、已有 rubric judge 的金融 text-to-SQL 任务**。前沿工作已经覆盖反事实 SQL 监督、步骤级信用、多 judge 集成和 verifier 校准，因此新增价值应落在这些机制和真实执行证据的组合，以及它们对局部信用分配的作用。

| 方向 | 核心假设 | 最接近的已有工作 | 我们要验证的增量 |
|---|---|---|---|
| 一：干预式验证 | 最小改变某步行为并重跑，比单次相关统计更能识别真实贡献 | CAPER、PCCC-RL [23][25] | 从 SQL clause／动作根因定位扩展到半开放过程 rubric 审计 |
| 二：多来源局部信号 | 执行锚点、过程探针和异质 judge 的组合比单一主观分数更可靠 | RaRE、TRCA [27][30] | 将可信度和分歧门控传递到 transition 级软过程奖励 |
| 三：因果充分性正则 | 在其他维度已知时仍能解释执行对错的规则，才值得占用训练信号 | RRD [26] | 从 judge 分数去相关推进到面向真实执行结果的条件增量筛选 |
| 四：可审计、可纠偏的 verifier | 已知答案的可执行探针可以估计 judge×criterion 的可靠性 | URW、Reward Hacking [28][29] | 用执行事实而非仅模板稳定性校准可信度，并用于加权、弃权或仲裁 |

### 7.1 方向一：干预式验证

**研究问题**：改变某一轮对目标 rubric 的满足程度，是否会系统性改变最终执行结果？这种局部效应能否比 corr 更可靠地筛选过程奖励？

**已有工作**：CAPER 已对 SQL AST 做 clause 级反事实干预并训练 Clause-PRM；PCCC-RL 已在长程 agent 中从保存的前缀恢复状态、替换动作并由冻结策略续跑。[23][25] **可能的创新点**：研究**半开放 rubric 维度是否具有可执行、结果锚定的局部效度**，并将这种效度用于规则筛选和局部信用分配。

**最小验证**：从成功和失败轨迹中选择关键 transition，对 schema 链接、过滤条件、查询修复和证据使用做最小编辑；保持前缀、数据库快照和后续冻结策略不变，分别重跑原始和编辑分支。主指标是成功率差及置信区间，翻转率只作辅助；同时记录其他维度是否被联动修改，防止把 off-target 改动误认为目标准则的作用。

**有效标准**：反事实效应应在重复采样中稳定，并能改善根因定位或信用排序；进入 RL 后，还应优于 outcome-only、静态 rubric 和 FineStep 式步骤信用基线。[24] 若只能改善解释而不能改善训练，应先定位为审计工具。

### 7.2 方向二：多来源局部信号

**研究问题**：最终执行结果之外，加入新证据、有效执行、单位／量纲和子目标完成等过程锚点，再结合异质 judge 的软评分和分歧信息，能否减少半开放维度的错奖？

**已有工作**：RaRE 已实现多 judge 的 logprob 置信加权和分歧 rollout 屏蔽；TRCA 已按 transition 评价 Evidence、Execution、Invalidity，并奖励首次取得的新进展。[27][30] **可能的创新点**：让**可执行证据校验多个 judge 的判定，并将可靠性传递到局部过程 advantage**；低置信时只关闭软过程项，不丢弃整条轨迹的执行学习信号。

**最小验证**：离线比较单 judge、朴素投票／均值、RaRE 式置信加权，以及“执行校验 + 过程探针 + 多 judge 评分 + 分歧门控”。除 EX 外，检查 criterion FP/FN、Brier/ECE、选择性风险—覆盖、无效和重复调用率，以及每轨迹 judge 成本。成对仲裁应交换 A/B 位置并允许 tie，不能把另一个 LLM 的偏好直接当作事实标签。

**有效标准**：分歧和置信度必须真正预测错误，多 judge 评分也必须优于最佳单 judge 和纯执行校验；若 naive committee 已足够，或分歧只反映主观性，就不应增加复杂门控。

### 7.3 方向三：因果充分性正则

**研究问题**：一条 rubric 在其他维度已知时，还能额外解释多少最终执行对错？这种条件增量信息能否比单纯相关性或协方差白化更好地选择规则？

**已有工作**：RRD 已覆盖递归拆分、语义去重和相关性感知加权。[26] **可能的创新点**：把优化目标从 judge 分数之间的去相关，转向对**真实执行结果**的条件增量解释，并和方向一的反事实效度交叉筛选。可写为 $S_k=I(v_k;z\mid v_{-k})$；样本不足时，用移除第 $k$ 维前后的正则化条件预测 log-loss 差作为可计算近似。

**最小验证**：按问题或数据库分组切分训练／测试，比较人工或均匀权重、无条件相关、RRD 式去相关、条件增量权重，以及“条件增量 + 反事实”组合。先在 held-out 数据上比较对错预测和 Best-of-N 选择收益，再做等预算短 RL。

**有效标准**：收益必须跨问题、数据库和学习阶段稳定，而非只拟合当前 judge。条件增量是统计信息而非因果证明；低频但必要的安全、范围和任务约束不能因增量低就自动删除。

### 7.4 方向四：Verifier 审计纠偏

**研究问题**：能否用已知满足／违反标签的可执行探针，估计每个 judge 在不同 criterion 和任务切片上的可靠性，再将估计用于奖励加权、弃权或升级仲裁？

**已有工作**：URW 已对冻结 verifier 使用改写模板和 conformal 校准生成逐 criterion 权重；Reward Hacking 研究则用跨模型家族参考 panel 区分 verifier failure 和 rubric-design limitation。[28][29] **可能的创新点**：让探针标签来自**真实 SQL／环境状态变化**，并检验这种可靠性估计能否改善 transition 级奖励，而不只是静态评价准确率。

**最小验证**：建立覆盖无效 schema、执行错误修复、重复调用、遗漏时间／单位／过滤条件、新旧证据使用和单库碰巧正确的探针集。按任务划分校准和测试集，比较原始判定、模板稳定性校准、可执行探针校准及低置信仲裁，报告错奖率、误拒率、证据不足率和校准成本。

**有效标准**：修复应同时降低错奖和误拒，并保持正常成功案例通过率；后续 RL 还需改善独立 EX／test-suite 表现，而不是只让训练 reward 上涨。分布漂移后应重新校准，不能把一次离线置信度当成长期保证。

### 7.5 验证顺序

第一阶段只做离线机制验证，优先方向四和方向二，确认 judge 错误能否被稳定测量、软信号是否提供执行锚点之外的增量。第二阶段验证方向一的局部反事实效应，并在样本量足够后检验方向三。第三阶段只将离线成立的方向接入等预算 RL，避免同时组合造成收益无法归因。

所有方向共享 execution-only、静态 rubric、直接多 judge、FineStep／TRCA 式过程信用等基线，固定 actor、数据、训练步数、rollout 数和评分预算。最终报告独立 EX／test-suite、关键约束违反率、无效调用和冗余交互、旧能力保持和总成本。**训练 reward 上涨不是主要证据；只有独立任务表现和局部机制证据同时改善，才值得把某个方向发展为方法创新。**

## 八、进一步思考：Reward System 的第一性

### 8.1 RL 需要的是什么样的反馈

RL 的核心不是有没有 rubric，而是环境能否为当前行为提供正确、有信息量、成本可承受的反馈。噪声反馈也可以用于学习，但误差不能系统性偏向某类错误行为，否则策略优化会持续放大偏差。

一个反馈机制需要回答五个问题：事实是否正确，目标是否对齐，能否区分当前好坏行为，能否定位局部信用，成本是否值得。更根本的评价方式不是只看 judge 准确率，而是看：

$$
\frac{\text{真实策略学习收益}}
{\text{采样、验证、评分和训练的总成本}}
$$

还要观察 policy 逐渐学会优化奖励后，奖励和真实目标之间的差距是否扩大。静态评价准确，不等于长期优化可靠。

### 8.2 Rubric 实际解决了什么

严格来说，rubric 不是把不可验证目标直接变成可验证事实，而是**把模糊目标拆成多个较容易判断的局部问题，再将判断压缩成奖励**。如果 judge 没有额外证据，这只是把整体猜测换成逐项猜测。

Rubric 的真正价值是分解目标、组织证据、提供局部反馈接口、支持审计修改，并将教师、人工或环境验证得到的知识压缩成低成本评价能力。因此，rubric 更适合作为奖励系统的组织形式，不应被当作事实来源。

从学习角度看，一条规则文字上正确，不代表它对当前 policy 有训练价值。规则可能已全部饱和，也可能只能区分表面特征。更直接的问题是：加入这条规则后，真实续训收益是否超过不加入它的分支。

### 8.3 从真实环境出发的选择

我们的 SQL 环境可以执行查询、保存状态、记录工具返回、修改动作后重跑，因此很多反馈不必让 LLM 猜。可以优先考虑：

- **直接测量状态变化**：执行是否从失败变成成功，是否获得后续真正使用的新证据，是否减少目标差距，是否产生重复或无效操作。
- **用环境分支估计局部信用**：从相同状态执行原动作和替代动作，再由同一冻结策略续跑，比较最终回报。高成本分支可以产生可信标签，再蒸馏给便宜的步骤评价器。
- **改造环境以暴露错误**：使用多数据库 test-suite、边界数据、空结果和执行故障，让遗漏条件和伪正确主动暴露，而不是只增强 judge 的文字判断。
- **直接测量效率和信息增益**：统计工具调用次数、无效和重复调用率、新信息比例、达到正确结果的轮数和实际成本。

环境奖励也不是天然正确。单一数据库上结果一致可能只是碰巧；环境过程奖励还应容纳多条合法路径，不能把某一种专家操作顺序当成唯一正确答案。

### 8.4 更适合我们的反馈结构

```text
真实环境状态和执行结果
        ↓ 产生高可信监督
环境分支、过程探针、任务验收
        ↓ 蒸馏成低成本局部评价器
Rubric / judge 组织反馈并补充软质量信号
        ↓
Policy 训练
        ↓
定期回到真实环境重新校验
```

执行正确性、状态变化和效率尽量由环境判定；局部动作贡献由环境分支和反事实重跑估计；无法程序化的软质量再交给 rubric judge。规则是否进化，最终取决于它能否带来真实学习收益，而不是它看起来是否合理。
